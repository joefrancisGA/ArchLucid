## Executive Summary

### `(A)` Overall headline readiness

ArchLucid V1 is **functionally complete and technically credible** for its contracted scope: request → execute → commit, Azure extractor ingest, compare/replay/graph, governance, audit, SCIM, executive ROI rollup, and a merge-blocking live trial E2E path. Recent **Operator Shell mitigation** (sample seed, tour copy, glossary empty states, sample purge lifecycle) and **operational hardening** (orchestrator transient DB retries, stall health check, ZIP streaming, idempotency on run creation, LLM budget surfacing) materially improved adoption surfaces since the last archive pass. The product still reads as an **operator shell for technical buyers**, not a self-serve consumer SaaS — and **real Azure context still requires a PowerShell → ZIP upload** by design (Tier 1 trust posture). Headline readiness is **solid mid‑80s**, held back mainly by **AI/agent operational edges**, **ingestion friction**, and **UX depth**, not by missing core pipeline code.

### `(B)` Procurement / market-motion realism

Enterprise procurement will still stall on **absence of CPA‑issued SOC 2 Type I/II** (self-assessment + CAIQ/SIG exist; attestation is post–V1.1 per [`V1_DEFERRED.md` §6c](../library/V1_DEFERRED.md)). **Manual Azure extraction** will face security-team scrutiny even with `-DryRun` and zero-credential posture — many buyers prefer continuous, role-based pull (Tier 2 is optional V1.x+, not a V1 GA contract). **Sales-led checkout** remains the default motion until commerce un-hold (Stripe live + Marketplace `Published`) — explicitly **V1.1**, zero `(A)` weight. Third-party pen test is **V2**; owner-conducted testing is documented. These are **`(B)` friction narratives**, not headline defects.

### Commercial picture

Pricing architecture (platform fee + seats + review overage, ROI anchor in [`PRICING_PHILOSOPHY.md`](../go-to-market/PRICING_PHILOSOPHY.md)) aligns with delivered value. **Cross-run executive ROI** ships (`GET /v1/roi/executive-summary` + Home panel). Trial funnel plumbing is in-repo with TEST-mode Stripe; **live transactability is owner-gated V1.1**. Remaining commercial gaps are **discoverability of sponsor artifacts** and **trial buyers hitting LLM hard caps** before conversion — product mitigations include operator 75% banner + budget pill and buyer-polished **`LlmUsageBandHint`** (approximate **percent remaining**, no dollar amounts). No `(A)` penalty for missing design partner or published reference customer ([`V1_DEFERRED.md` §6b](../library/V1_DEFERRED.md)).

### Enterprise picture

Strong enterprise primitives: **database-per-tenant** isolation, Entra/OIDC/SAML/SCIM surfaces, RLS option, private-endpoint Terraform modules, 78-type audit catalog, governance workflows. Adoption blockers are **procurement assurance timing**, **manual ingest workflow**, and **Operate-layer enablement** (governance/alerts require deliberate configuration and extended nav). ITSM/Teams/Slack/webhooks are **V1.1 contract** — correctly out of `(A)`.

### Engineering picture

Modular .NET monorepo with contract tests, live API E2E gates, orchestrator retry documentation ([`ORCHESTRATOR_RETRIES.md`](../library/ORCHESTRATOR_RETRIES.md)), and explicit deferral inventory. Residual risks: **custom authority orchestration** (mitigated, not eliminated), **LLM cost estimation drift**, **audit parity gaps** on some mutating paths, and **Terraform brownfield `state mv`** hygiene. Durable Task Framework and outbound MCP remain correctly deferred. Dependency graph audit (2026-05-23) found **13 illegal `ProjectReference` edges** — most critically `ArchLucid.Persistence` carrying 6 upward domain references (Decisioning, ArtifactSynthesis, ContextIngestion, KnowledgeGraph, Provenance, Notifications) that invert the hexagonal boundary, and `ArchLucid.Application` naming both `Persistence` and `Integrations.AzureExtractor` directly; **13 `Architecture.Tests` assertions are absent** to guard these edges (see #32, #33). **Bounded-context audit (2026-05-23):** `KnowledgeGraph` and `Retrieval` are genuinely isolated (no `Contracts` reference, own domain models). **Decisioning, AgentRuntime, Provenance, and ArtifactSynthesis** partially share a god-model through `ArchLucid.Contracts` — internal types (`DecisionNode`, `DecisionTrace`, agent evaluation interfaces, bloated `AgentExecutionTrace`) leak across context boundaries and couple merge engine, execution trace, and explainability surfaces (see #34, #35).

## Top 14 Most Important Weaknesses

1. **Manual PowerShell → ZIP Azure ingestion** remains the default path to production-faithful cost/evidence — high trust, high friction.
2. **LLM monthly hard cap ($75)** can still halt real-mode runs after warnings — trial conversion risk when buyers exhaust budget before finalize.
3. **Operator-shell UX** — powerful but intimidating; legacy `run`/`runId` vocabulary leaks to buyers on some surfaces.
4. **Sponsor artifact discoverability** — ROI APIs exist; the path from Home to board-ready exports is not obvious.
5. **Custom authority orchestration** — retries and health checks help, but state-machine complexity remains an operational liability vs DTF (deferred).
6. **LLM cost estimation tuning gap** — limited structured telemetry comparing pre-call estimates to post-call token usage.
7. **Buyer-polished tenants lack budget visibility** — operator-only LLM pill/banner; trials may hit hard stop without ambient context.
8. **Compare/Graph workflows** still assume technical run ID entry in places instead of pickers from recent reviews.
9. **Audit coverage gaps** on select mutating/export paths ([`AUDIT_COVERAGE_MATRIX.md`](../library/AUDIT_COVERAGE_MATRIX.md)) — compliance reviewers will ask.
10. **Thin in-repo custom agent handler guide** vs V1 GA documentation commitment ([`V1_SCOPE.md` §2.18](../library/V1_SCOPE.md)).
11. **Terraform brownfield `state mv`** — IaC labels say `archlucid`; remote state may still list `archiforge` addresses.
12. **Operate-layer activation tax** — governance, alerts, and audit exports require config + nav disclosure; easy to under-use Professional-tier value.
13. **Assembly dependency graph violations** — `ArchLucid.Persistence` references 6 domain assemblies (Decisioning, ArtifactSynthesis, ContextIngestion, KnowledgeGraph, Provenance, Notifications) in violation of clean hexagonal layering; `Application` directly references `Persistence` and `Integrations.AzureExtractor`; 13 `Architecture.Tests` assertions are absent to guard these boundaries from regressing further.
14. **Contracts god-model / bounded-context bleed** — `DecisionNode`, `DecisionTrace`, agent evaluation interfaces, and bloated `AgentExecutionTrace` live in `ArchLucid.Contracts` though they are Decisioning or AgentRuntime internals; `IProvenanceBuilder.Build()` takes types from four contexts in one signature; `AgentResult` embeds `ManifestDeltaProposal` (Decisioning merge schema).

## Top 6 Engineering Risks

1. **Authority orchestrator state complexity** — long-running pipelines, queue resume, and timeout cancellation can leave runs in ambiguous states under rare failure combinations.
2. **LLM cost estimation inaccuracy** — hard caps depend on estimates; drift causes surprise blocks or COGS overshoot.
3. **Idempotency UX gap** — server supports keys; clients may not send them consistently under retry storms.
4. **Audit emission gaps** — some flows lack durable audit rows; forensic completeness risk.
5. **Terraform state drift** — legacy resource addresses in remote state complicate safe IaC iteration.
6. **Large ZIP ingest** — streaming mitigates memory risk; malformed or adversarial ZIP edge cases remain a DoS surface without strict rate limits at edge.
7. **Layer inversion in infrastructure** — `ArchLucid.Persistence` (L3 adapter) references 6 domain assemblies (L1); without architecture test guards these couplings can silently grow, making persistence backend swaps or isolated domain testing progressively harder. `Application` also names the concrete `Persistence` assembly rather than declaring ports in `Contracts`.
8. **Contracts as shared god-model** — context-local types in `ArchLucid.Contracts` force Decisioning, AgentRuntime, Provenance, Application, Persistence, and Api to recompile together when merge-engine or trace-recorder internals change; distinct from assembly-reference inversion (#33) but equally costly for long-term modularity.
