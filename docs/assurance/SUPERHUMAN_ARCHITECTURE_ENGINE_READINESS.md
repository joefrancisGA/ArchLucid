# Superhuman architecture-engine readiness review

**Review date:** 2026-09-20

## Decision

**Expert-beating / superhuman architecture performance is not demonstrated.**

That is an evidence conclusion, not a negative judgment about the implementation. The engineering program now has substantially stronger machinery for establishing the claim honestly, but the decisive held-out and independent-human evidence does not yet exist.

## Evidence tiers

| Tier | Status | Current evidence |
|---|---|---|
| A. Structural/software assurance | Strong | compile/architecture constraints, SQL/API/workflow tests, golden corpus, failure visibility, provenance/claim guards, mutation infrastructure |
| B. Independent semantic development assurance | Stronger after this program | synthetic SecureNow worlds, metamorphic suites, credibility tripwires, brute-force reachability/cut-point/RBAC truth oracles, five deep visible development cases |
| C. Sealed held-out architecture performance | **Not demonstrated** | 25 holdout slots and integrity governance exist; expected truth/results intentionally remain external and unexecuted |
| D. Blind independent human comparison | **Not demonstrated** | grading protocol exists; M-302 has not been executed |
| E. Superhuman/expert-beating claim | **Not demonstrated** | requires repeated Tier-C/D evidence on defined tasks/populations |

## What is now defensible

It is defensible to say the product has:

- multiple independent assurance mechanisms rather than unit tests alone;
- explicit failure/uncertainty states;
- deterministic truth boundaries for important SecureNow facts;
- independent reference algorithms for bounded security questions;
- protected holdout methodology;
- tooling to measure false positives, unsupported certainty, determinism, cross-surface consistency, defect discovery and regression memory.

## What remains before a stronger claim

1. Populate the sealed holdout cases and answer keys outside normal development context.
2. Run the tournament against frozen product/model versions.
3. Execute the blind 2–3 architect directional panel.
4. Adjudicate misses and false positives; add regression/prevention without exposing future holdouts.
5. Repeat on a larger held-out set and external architect population.
6. Report dimensions, hard-gate violations, time/cost and uncertainty; do not hide them behind one score.

The engineering system is increasingly ready to **measure** superhuman performance. The performance claim itself remains unproven.
