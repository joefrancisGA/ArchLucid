# Assurance architecture review

The assurance system itself can be wrong. Review it as production architecture.

## Tautology checks

Flag a test or benchmark when:

- expected output is generated by the production algorithm under test;
- a golden file is automatically re-recorded without independent review;
- a reference implementation shares the same helper responsible for the disputed semantics;
- an AI reviewer is called “independent” while receiving identical instructions/context and using the same reasoning path;
- a benchmark case was visible during prompt/model tuning but later described as held out;
- a clean test result can coexist with hidden engine failures;
- a metric averages away a must-not-fail violation.

## Corpus integrity

- Visible development cases may drive iteration.
- Held-out expected truth must remain outside normal development context.
- Synthetic worlds must state truth before production execution.
- Metamorphic transforms must be semantically irrelevant by inspection.
- Reference algorithms should be intentionally simpler/slower than production.

## Measurement integrity

- Preserve denominators.
- Record skipped/not-applicable/failed separately.
- Keep raw dimensions beside aggregates.
- Do not turn capture-recapture into a correctness probability.
- Do not infer expert superiority from visible fixtures.

## Review cadence

Run this review whenever a new assurance mechanism is added and before strengthening public correctness/superiority claims.
