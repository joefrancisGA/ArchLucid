# Historical replay descriptor and artifact completeness

The versioned descriptor records the original product, project scope, run, snapshot and finding, stage dependencies and coverage, accepted attempts, effective evidence and policy, execution versions, and artifact identities and digests. Roles distinguish applicable original output, trace, evidence, graph, policy/exception/asset assertions, configuration, executable/runtime dependencies, checkpoints, independent verification and human decisions. Additional mode-specific requirements let a sealed record mark otherwise optional artifacts as essential. Versions, collection timestamps and observed evidence coverage are explicit. A descriptor contains metadata and hashes, not prompt text, response text, credentials or new retained copies of artifacts.

## Existing sealed records and authorization

The ArchLucid anchor checks the scoped run, snapshot, trace and manifest identities and uses the existing manifest hasher. It carries existing evidence and policy pin digests where recorded. Pin digests do not establish that the referenced bytes are available. Its canonical commitment is separate from the exact-byte hashes of the retained artifacts. The SecureNow anchor checks the scoped inventory snapshot and its recorded content hash and capture coverage. This anchor does not by itself establish a historical finding's identity or truth. The independent descriptor commitment ties the original run/finding and required output to that capture. Accepted ArchLucid model metadata can be projected from the trace for the explicitly selected task, trace and attempt, but parse success, a blob pointer and inline traces are not proof of exact retained input bytes.

The completeness service requires the anchor and descriptor digest from an already authorized, independent commitment source. Bind the detached digest through the existing scoped sealed evidence or audit boundary; do not derive the expected digest from the candidate or add it retroactively to a manifest that already seals the original run. The descriptor uses the existing canonical dependency hashing helper with a new schema identity. No legacy hash projection, repository write, new artifact store, API change, execution path, or host registration is introduced. The scoped artifact reader contract is for callers adapting authorized existing readers, not an arbitrary file, URL, raw trace or provider runtime. The authority adapter uses the existing project-scoped bundle repository to read one exact UTF-8 artifact by manifest and artifact ID; it never substitutes bundle contents for independently retained raw prompts or responses. Existing records without the detached commitment remain unchanged and receive an explicit legacy or unavailable readiness status.

## Mode-specific assessment

- **Reconstruction** requires the original output, source evidence, policy and trace, plus the recorded stage lineage and any explicitly required references. A complete reconstruction of what was recorded may still report that the underlying collection was partial.
- **Recorded typed-input readiness** also requires compatible execution versions, exact historical configuration, runtime dependencies, executable, stage outputs, accepted typed inputs and tool results as applicable. It does not establish what a missing raw response contained.
- **Recorded raw-input readiness** additionally requires exact historical prompt and response artifacts and their bound accepted attempts. A redacted or truncated trace can never stand in for the original bytes.

The verifier checks required bytes by scope, role, attempt, schema, length and digest, with bounded streaming reads and forwarded cancellation. It refuses wrong-scope or wrong-attempt receipts without publishing their contents, distinguishes tampering and incompatibility, and reports unresolved evidence and lifecycle availability without reopening erased or expired data. Eviction of an optional cache has no effect; a checkpoint promoted to a required historical artifact must actually be retained. A compatible runtime selection is supplied independently. No program is loaded or executed.

The focused Release lane exercises complete paired product fixtures and retained-byte tampering, scope/lineage violations, unavailable or derived artifacts, version mismatches, legacy records and immutable history, alongside the existing replay prepare and SecureNow offline replay tests. FND-095 provides isolated recorded-input execution; FND-096 governs retention, restoration and loss; FND-097 evaluates historical equivalence and independent claim revalidation. This slice does not assert that existing customer histories have complete evidence or that an existing product path has been migrated.
