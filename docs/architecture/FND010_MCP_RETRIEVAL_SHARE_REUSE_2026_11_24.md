## Findings and narrow reuse
- All three HTTP tools used the trusted tenant/workspace/project scope and general ReadAuthority policy, but invoked unrestricted mixed-corpus retrieval before filtering the returned hits. Prior-decision search lacked the architecture-run sharing boundary; even platform-only policy/price tools could expose unrelated private candidates to ranking, critique or summarization before filtering.
- Reuse the authenticated IAskEvidenceAccess adapter (existing canonical share gate) and bounded AuthorizedEvidenceRunResolver for prior decisions. All three routes reject an absent actor or incomplete scope. Resolve and authorize using the exact trusted scope used in the request; incomplete enumeration returns generic 409; an empty visible set returns empty results before vector dispatch. Keep the existing route body shape and general role policy; no caller-supplied scope or authorization set.
- Require an explicit server-authorized evidence run set on the existing public PriorDecisionSearchAsync tool method; no legacy unrestricted overload. Empty/zero-only sets do not search, null is rejected. Policy and retail tools explicitly carry an empty tenant-evidence set and opt into existing platform access rules; policy-pack assignment resolution remains in the retrieval service. Preserve the existing tool-defined corpus selection, output truncation, top-k cap and post-filter as defense in depth. The server-owned run set is copied and zero IDs removed.
- Add optional exact corpus constraint to the existing RetrievalQuery, intersecting the complete tenant/platform expression in Azure and checking before cosine ranking in memory. Carry the constraint through candidate and iterative retry clones. Explicitly select Azure prefilter for either run or corpus restriction; graph expansion is not used when either restriction is present. This is an extension to the existing retrieval contract, not a new authorization policy or package. No search schema change or paid endpoint provisioned.
- The direct in-process prior-decision tool now requires a trusted caller to supply an authorized run set; it is not a self-authenticating capability. HTTP is the only production caller confirmed by indexed search. Existing internal agent retrieval without the constraint is not remediated by this patch.
