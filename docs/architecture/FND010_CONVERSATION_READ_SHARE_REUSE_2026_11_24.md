## Findings and reuse
- Both existing GET routes enforce general read/tier and scope but not architecture sharing, current authorization of run/comparison anchors, actor or per-turn grounding provenance. Paged listing exposed raw scope-wide count and headers; direct message GET returned all recent rows. Draft intake can also populate unanchored threads with no Ask proof.
- Reuse the already registered IAskEvidenceAccess (canonical run share evaluation), AuthorizedEvidenceRunResolver (bounded project discovery), and AskHistoryEvidenceScope.SelectVerifiedTurns (same actor, same thread and still-authorized evidence set). No additional ACL or control family. Reject incomplete scope/anonymous or generic actor, invalid/archived/out-of-scope threads, incomplete comparison anchors, and denied runs before message reads. Cache exact run share decisions per request only. For direct anchored GET, incomplete project enumeration falls back to the checked anchors only, matching Ask; unanchored GET denies. Missing, denied or no provably visible turns return the same generic thread 404. Existing legacy rows remain in storage.
- Listing enumerates at most 500 candidate headers in bounded pages, never publishes raw total, and requires at least one verified completed turn in the recent 40-message window. Pages are built after authorization using existing PagedResponseBuilder; raw hidden thread count is not returned. Reorder by visible completion time and deterministic thread tie-break; project a generic title and visible first/last completed-turn timestamps so another actor's activity/title is not disclosed. Incomplete/oversized enumeration returns generic 409 rather than presenting a misleading total. This may reveal the coarse fact that the authorization budget was exceeded, not a count. Offset enumeration is not transactionally snapshot-consistent; duplicate rows or inconsistent totals fail closed.
- Direct message GET checks current visibility within the existing 500-message maximum before applying take. Returns only verified completed turns (or their trailing messages if caller limits take). V1 provenance proves question text, not the original user-row identity; expose a deterministic display-only question ID, verified completion timestamp and empty metadata rather than an unrelated matching row's ID/timestamp. Assistant IDs and citation metadata are retained, internal actor/evidence proof omitted. No storage mutation.
- This deliberately hides preexisting unproven Ask and draft-intake history, and new platform-corpus turns that #8037 intentionally does not mark replayable. A legacy thread may become visible after a new verifiable Ask completion, without exposing prior turns. Existing response shapes remain, but timestamps/IDs/list visibility semantics change for security. Direct GET may find a verified older turn within its 500-row window that the 40-row listing window does not show. Raw message bodies are still internally hydrated after scoped header/anchor checks because the repository has no metadata-first proof projection; unverified text is never sent to the client or model by this controller. No claim of atomic permission revocation, SQL-level actor enforcement or full scalability.
