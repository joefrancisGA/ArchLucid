## Findings and changes
- ID-only direct inspect previously hydrated payload before establishing share authority. Use the existing scoped GetRunIdByFindingIdAsync metadata lookup and canonical IArchitectureShareAccessGate; missing/empty/denied owners produce the same generic finding 404. Pass ExpectedRunId for both full and metadata-only reads, validate returned run and finding ID before seal/inventory checks or enrichment. Retain existing role/tier, seal, inventory, reasoning, trust and response behavior. Use the same scope instance through these checks.
- Run-specific inspector already passes the controller run read boundary. Its downstream RunFindingsInspectStage previously loaded the newest matching logical finding ID and only rejected a different owner after hydration. Bind its existing read options to the requested, parsed run before payload access, then verify returned identity. Existing lifecycle guard retained.
- External tracking previously queried by tenant and logical finding ID; the existing optional snapshot ID constrained finding status only, not ITSM/disposition. Reuse existing enrichment mapping/URL builder with an explicit authorized-run repository projection. SQL joins ItsmFindingCorrelations.FindingRecordId to the finding record, snapshot and active run, verifies tenant/workspace/project on both sides, then selects/aggregates only correlated rows belonging to the authorized run. Null or unproven correlation record IDs are not eligible. In-memory backend cannot establish relational record ownership, so its new projection returns empty rather than falling back to tenant-wide logical-ID results. Existing legacy ListForFindingsAsync callers unchanged pending separate audit. No schema change or new authorization control family.
- The inspector's follow-up disposition pointer and active waiver queries previously bound only project scope and logical finding ID. When ExpectedRunId is supplied (including the existing Ask path), require review event / waiver RunId to equal the selected run. Null or different run IDs are excluded. The existing unbound repository behavior remains for callers that have not yet adopted the explicit contract. The authorized tracking projection does not overwrite the inspector's disposition with another logical-ID event.
- Deliberate limitations: older links, review events and waivers without provable run ownership may no longer appear in the constrained inspection paths. Original data is not modified or deleted. No claim of transactional revocation across subsequent reads. SQL shape validation is not live database execution.
