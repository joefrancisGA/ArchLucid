# FND-010 SCIM/project ACL authorization integration

The SecureNow exchange's `IEvidenceEntitlementAuthority` is now backed by the existing SCIM user repository and project-role assignment repository. Each read checks the trusted request scope, directory object identity, current active/nondeleted SCIM membership, and current project role of at least Reader. No JWT role or client-supplied entitlement claim bypasses the project ACL. A revoked project role or deactivated SCIM user denies access on the next repository lookup, assuming the repository is current and uncached.

**Scope and release caveats:** This is project-level authorization for run snapshots, not an evidence-specific ACL; `EvidenceId` is validated for presence but is not independently authorized against a run ownership table. The gate still checks the broad ReadAuthority policy. Authentication must validate the directory object claim's issuer. Current project-role storage must be wired in DI. Real-host HTTP tests with valid and foreign-tenant tokens remain outstanding. Existing feature flag remains disabled until those checks, CI and security review pass. This PR does not implement an entitlement issuance service, because it uses authoritative server-side ACL reads rather than minting claims.
