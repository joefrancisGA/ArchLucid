# FND-061 authorization before retrieval-indexing evidence

Retrieval indexing is system-owned work, not a user-delegated export. On baseline `b6a129981dd31382a01e48feec67475c2553e2c2`, the sole production enqueue caller was `AuthorityCommittedPipelineFinalizer`. It records the scoped run transition to Committed before enqueueing the exact run and scope, in the same SQL transaction when the store supports one. The worker relies on this write boundary and the claimed row, not on a queued user identity or a synthesized principal.

Before using evidence stores or caches, the worker checks that the four job IDs are explicit, that the job does not widen any active drain scope, and that the exact tenant/workspace/project/run matches uncached metadata. Archived, incomplete, or foreign runs are not accepted. The worker then looks up the precise manifest ID from that header, verifies its run, scope, and evidence anchors, and checks its seal. Both persistence adapters consume those already-verified anchors and do not reread a potentially stale run header or manifest. An invalid job or missing resource takes the skip-as-processed path. A missing or corrupt seal takes the existing terminal failure path without graph, findings, artifact, or indexing work.

The focused FND-061 check exercises denied scope, run, and manifest cases, invalid seals, authorized indexing, replay, and equivalent SQL/in-memory adapter behavior. This slice adds no migration, modifies no historical rows, and does not launch a reindex. It does not certify the Cosmos or post-commit projection workers, or make the check required for merge.
