## Confirmed omissions and changes
- Ordinary/streamed Ask previously derived effective run/base/target from request or persisted thread, then appended a user message, read history and loaded protected run/manifests/provenance without architecture-sharing evaluation. Reuse the exact existing canonical run-share decision through a host adapter backed by the authenticated HTTP principal. Non-HTTP/unconfigured host denies by default. Explicit anchors checked before creating a thread; persisted anchors independently checked before any history or writes; reject anchor changes on an existing thread. Existing role, scope, manifest/inventory and lifecycle behavior retained. No new ACL model.
- Both workspace and run-grounded Ask previously performed unrestricted project-wide vector retrieval. Extract #8035's existing bounded scoped candidate enumeration into a shared utility, leaving its authorization callback with the existing gate. Ask passes the authorized run allowlist to #8035's pre-ranking filters. If project enumeration exceeds five 100-row pages, workspace Ask fails closed; anchored Ask uses only already-authorized explicit/stored runs. No unrestricted fallback. SQL fallback is from the already-authorized structured run detail. Existing retrieval budget/AI stages and platform policy assignments remain; graph expansion remains disabled on constrained paths.
- Old history did not record which runs or actor supplied an answer and could contain earlier unrestricted evidence. New server-written assistant metadata records thread-salted hashes of the actor key, conservative authorized evidence run set and exact question. Replay only completed paired turns for the same actor whose entire run set is still authorized. No raw actor/run IDs or duplicate question text in this proof. Legacy/malformed/foreign actor/revoked-run turns, ambiguous question pairing, generic fallback actor and platform-corpus turns are omitted from AI context; durable old messages are not deleted. This is an intentional compatibility tradeoff for follow-up context, not a new identity or sharing scheme. The trusted server-side metadata is not a signed cross-system artifact.
- Finding Ask previously loaded full evidence after reading history, used unanchored threads, and indexed private finding turns as platform-sentinel conversations (empty tenant/workspace/project). Add scoped run-ID-only lookup using existing inspect joins/order; Dapper full/metadata inspect now optionally binds the expected authorized run, in-memory demo lookup provides a candidate only and full lookup verifies actual finding. Authorize owner before full hydration, verify owner again, keep inventory guard, and require finding conversation to be anchored to that run. Stop indexing finding conversation turns; persist/audit as before. Legacy unanchored finding threads require a new anchored thread. Both vector backends now reject sentinel Conversation chunks, including older indexed rows; authorization-constrained platform searches additionally admit only recognized platform corpus types while retaining policy-pack assignment filters.
- Existing ConversationController direct list/message routes and draft-intake history are independent, not secured by the Ask service patch. They are the next audit priority, especially preexisting thread rows whose origin cannot be proven. MCP and internal agent project retrieval also require separate caller-specific analysis. Ordinary conversation indexing remains an independent residual for unconstrained tenant search; sentinel conversation indexing is stopped. No claim of live index deletion, fleet-wide revocation, or transactional share revocation.
