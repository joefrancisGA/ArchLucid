# Full GraphRAG expansion benchmark cohort

The capacity benchmark executable now accepts `graph-expansion` as a workload. Unlike the lower-level collector benchmarks, this cohort calls the production `GraphRagNeighborExpander.ExpandAsync` method using the real retrieval hit models, typed GraphSnapshot and an in-memory Moq `IGraphSnapshotRepository` returning a deterministic generated graph. It checks that the snapshot was requested once, neighbor hits were returned, and output is score-ordered. The existing dedicated-process measurement harness records CPU, wall time and sampled working set. The CI workflow invokes the new cohort three times with separate processes.

This is a component integration benchmark, **not an actual SQL/blob retrieval, vector search, embedding or end-to-end RAG query**. The fixture is a generated chain, and repository I/O is mocked, so the measurements cannot predict database latency, remote calls, tenant fleet behavior or production throughput. Memory samples are not guaranteed peaks, and CPU includes initialization of the mock and expander. No tenant secrets, live endpoint, production scope or infrastructure configuration are touched. Build and CI results must be inspected before using any benchmark artifact as evidence.
