## Findings and implementation
- Reasoning used scoped draft retrieval and lifecycle guard but did not check linked architecture sharing before grounding. It trusted the stored ConversationThreadId and read raw conversation history (including any review, comparison or other draft thread in scope). New host adapter methods reuse the canonical share evaluator and existing execute/read authority probe: a linked draft requires read AND decide, legacy unlinked drafts require the exact identified creator and execute authority, malformed or inaccessible prior/spawned run anchors deny. Missing/unidentified actor, empty scope and mismatched returned draft identity/scope deny before history or LLM. Existing state-machine guard retained.
- Resolve thread header first. Only scoped, nonarchived, unanchored threads can be considered for draft history. Reuse AskHistoryEvidenceScope completed-turn validation with an explicit draft-specific property and actor/draft/architecture-bound digest. Prior evidence run keys must remain authorized. Ordinary Ask proof is not accepted for draft reasoning and draft proof is not accepted by ordinary Ask or direct conversation reads. Only verified same-actor, same-draft turns enter model context. Do not append to an old pointer without a verified turn. Create a fresh thread, leaving old data stored, if missing, foreign, legacy, revoked or unproven; current question enters the prompt exactly once. New draft assistant turns store server-written proof. No new ACL family or database schema.
- Old thread persistence used broad UpdateAsync and could clobber a concurrent edit. Use a narrow conditional repository operation based on scoped draft ID, exact architecture/status, timestamp, and existing canonical document fingerprint. Reject absent/mismatched revision hashes rather than overwrite. Dapper updates only the document/pointer, hash, read model and update timestamp; in-memory compare-and-swap preserves other fields. Cache decorator evicts using the existing eviction path even on rejection or exception. Failed binding returns conflict before conversation writes or LLM. Recheck returned identity and authorization after successful binding. A newly created thread may remain orphaned if the CAS loses; retention can clean it up.
- Deliberate compatibility choices: preexisting history without proof is not replayed, linked drafts with read-only share cannot reason/mutate, different actors start separate fresh conversation history and can replace the draft's current pointer, unhashed legacy draft revisions cannot establish a new thread until repaired. The general conversation API continues to hide draft-only proof. Raw scoped draft and unanchored message windows are hydrated internally before the final per-resource/proof decision; no unverified content is sent to the model. No claim of transactional permission revocation or full draft CRUD/clone authorization. A broader draft data lineage and authorization audit is separate.
