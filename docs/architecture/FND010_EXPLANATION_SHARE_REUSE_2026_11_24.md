## Confirmed gaps and corrections
- All six HTTP routes required general ReadAuthority (holistic critic additionally ExecuteAuthority) and existing sealed-manifest checks but did not evaluate run sharing before evidence hydration. Require the existing injected gate for single-run explain, aggregate, finding explainability, finding LLM audit and holistic critique. Both compare inputs must pass before either detail read or comparison facade. Empty GUIDs deny before payload reads. Preserve existing manifest/hash, lifecycle, pin/inventory, response mappings, telemetry and advisory role policies; holistic detail read now also participates in existing conflict handling.
- Aggregate and holistic routes can enter the explanation-summary cache. Per-request authorization now occurs before those paths, so a subsequent revoked request cannot get a cached response from these endpoints. Cache key previously held only run ID and row version, not the complete tenant/workspace/project identity. Version the existing key and add all three scope IDs; retain row-version invalidation and normal hit semantics. Existing internal/demo/export/pilot/trust-card consumers of IRunExplanationSummaryService remain separately reviewable; cache is not an actor authorization grant. No change to their execution authority.
- Finding LLM audit previously took a preferred trace ID from finding data and looked it up without a run-specific predicate. Resolve the preferred ID within the existing scoped run trace collection via AnalysisRunIdCanonicalization, additionally require returned trace RunId to match the authorized run, and retain typed fallback within that same collection. Missing/foreign IDs cannot expose foreign prompts. Existing redactor remains in use. This removes the fast direct-ID lookup and may load more same-run trace rows; a scoped point lookup could be a later optimization. Trace redaction is not a substitute for sharing authorization.
- No new authorization kernel, ACL model, cache family or schema introduced. No changes to FindingInspectController yet; its ID-only lookup needs the already implemented finding-to-run identity projection and a separate review of external tracking enrichment.
