# SecureNow executive proof packet — fill guide

> **INTERNAL GUIDE.** This maps the empty packet to evidence owners. It does not populate customer outcomes. Empty or missing evidence stays **NOT COLLECTED**, **NOT VERIFIED** or **NOT MEASURED**.

## Decision summary fields

| Packet field | Evidence source | Owner and rule |
| --- | --- | --- |
| Organization, tenant and subscriptions | Authorized written pilot scope | Owner confirms permission and bounded scope |
| Baseline and verification capture IDs | Capture records and timestamps | Operator records completeness and gaps |
| Key concern and cited path IDs | Completed path analysis export | Analyst cites hops and uncertainty; no exploit claim |
| Confidence and limitations | Collection and analysis status | Analyst preserves missing or partial evidence |
| Recommended cut point | Reviewed advisory analysis | Analyst describes tradeoffs; customer approves action |
| External change and postcondition | Customer change record plus later capture | Customer attests change; SecureNow does not apply Azure changes |
| Remaining risks and gaps | Verification review | Analyst records unresolved paths and insufficient evidence |
| Decision owner and review date | Sponsor readout | Sponsor or customer decision owner records disposition |

## Claim table fields

- **Consequential path:** completed capture, cited hops and ranking dimensions.
- **Leverage:** named advisory cut point and affected ranked paths.
- **Implemented change:** an external human attestation, not an in-product action.
- **Corrected condition:** later successful capture, chronology, completed analysis and substantive postcondition. Otherwise use **NOT VERIFIED**.
- **Investigation effort:** comparable task definition, baseline and after-product minutes, sample size and limitations. Do not call this ROI by itself.
- **Control evidence:** snapshot/verification association and human analyst disposition.

## Review sequence

1. Operator checks scope, freshness, completeness and source links.
2. Analyst fills only fields supported by reviewed evidence.
3. Customer change owner supplies any external attestation.
4. Sponsor reviews limitations, objections and follow-ups.
5. Owner applies the release claim gate before any external share.

## Explicit exclusions

Do not add fixture values, invented hours, fee amounts, avoided-breach dollars, savings guarantees, compliance certification, CPA-issued SOC 2 status or third-party penetration-test claims. Keep the packet template empty until a real pilot supplies authorized evidence.
