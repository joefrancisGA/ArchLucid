# SecureNow Evidence Lab — native question reconciliation

This increment turns the original evidence ZIP audit, the native C# offline replay, and an export of the **real** SecureNow question API into an auditable comparison. It does not call Azure, SQL, APIs, paid services or LLMs. It does not alter questions, risk acceptance or evidence.

## Input provenance

Prepare three local (tenant-confidential) inputs:

1. The V1 ZIP audit's **\`evidence-coverage.json\`** with package SHA-256 and subscription records. Generated by \`scripts/securenow/evidence_lab.py\` on the original ZIPs.
2. Native C# replay JSON for each subscription: \`<subscriptionId>.native.json\` inside \`--native-dir\`. Generate from the **same ZIP** with \`tools/SecureNow.QuestionReplay\`.
3. A current, independently exported **\`GET /v1/infra-evidence/snapshots/{snapshotId}/questions\`** array saved as \`<subscriptionId>.questions.json\` inside \`--questions-dir\`. Keep it in private local storage. Each item must carry \`subscriptionId\`, \`snapshotId\`, \`source\`, \`questionKey\`, \`resourceId\`, and \`evidenceFingerprint\`.

Do not commit any customer ZIPs, API exports, input manifests or resulting reports.

## Run

\`\`\`bash
python3 scripts/securenow/reconcile_replay.py \
  --coverage-report ./private/lab-results/evidence-coverage.json \
  --native-dir ./private/native-replay \
  --questions-dir ./private/questions \
  --out ./private/lab-results/reconciliation.json \
  --fail-on-drift
\`\`\`

\`--fail-on-drift\` exits 3 when a subscription is missing one of the two question inputs or when the inventory-question slice has a mismatch. Without that option the program still reports \`REVIEW_REQUIRED\`, never silent success. Validation errors or mismatched package hashes exit 2.

## Exact comparison semantics

- The native C# replay **only** generates the *InventoryEvidence* portion of the question queue. PolicyPack and InferredConnection items from the full API are counted separately, not flagged as native-only mismatches.
- Identity is (\`source\`, normalized \`questionKey\`, SHA-256 of normalized resource ID).
- The match compares \`evidenceFingerprint\` after normalization; answers/statuses are not carried over.
- Differences are \`nativeOnly\`, \`apiOnly\`, or \`fingerprintDrift\`; all require independent investigation. A mismatch does not prove an engine defect, because the complete SQL-stored graph has extra projections and optional evidence.
- The native report's **package SHA-256 must equal** the V1 ZIP audit report hash. Invalid native schema, counts, duplicate questions, mixed snapshots, or foreign subscription IDs fail instead of being compared.
- The original API export may have been saved from a different capture or policy version; **this tool cannot authenticate the export's snapshot provenance**. \`questionSourceSnapshotVerified=false\` always. A matched partial slice does **not** establish full replay parity.
- A missing native report or missing API export is \`NOT_COMPARABLE\`, never zero questions or green security posture.

Output contains only IDs/hashes, status and difference reasons, not raw ARM IDs or question text.
