# SecureNow peak-memory forecast evidence (MEM-01 through MEM-03)

The graph workload profiler now samples process working-set bytes and managed heap size at approximately 10 ms intervals while the operation runs, and records a process-wide managed allocation delta with `GC.GetTotalAllocatedBytes(false)`. The samples include final observations. These are **not isolated per-operation allocations, guaranteed peak resident memory, or guaranteed peak managed heap**. Short-lived peaks can be missed, and concurrent process work can contaminate readings.

Existing synthetic graph benchmark cohorts emit the enhanced profile without enabling production telemetry or changing evidence and admission rules. The chain fixture now caps maximum traversal depth at the implementation-supported 64 hops; prefix counts correspond to the bounded depth rather than full 5,000-node traversal. The current benchmark does **not** run a clean dedicated process per graph cohort, so its output cannot be attested as dedicated-process calibration.

`SecureNowPeakMemoryForecast.Estimate` only uses caller-supplied samples explicitly labeled `DEDICATED_PROCESS_SAMPLED`, ignores truncated samples, requires two same-cohort observations bracketing node count, edge count, depth and prefix count, and reports the maximum sampled working-set observation plus a configurable 1–4× planning multiplier (default 1.5×). This is an **advisory planning budget**, not a statistical prediction interval or guaranteed safe memory ceiling. Without adequate measured input it fails closed; it does not automatically adjust worker sizing, memory quotas or production admission.
