## Outage and release evidence

- The unit suites cover Retry-After delta and date, remaining budget, logical-call saturation and cancellation, safe read vs unsupported POST, separate breaker state, lost webhook response and redelivered queue payload, ARM query allowlisting, catalog pagination, and legacy CLI write protections. Fakes terminate all HTTP requests.
- SQL evidence must prove one reservation winner across independent connections and a fresh store, no cross-tenant or cross-destination collision, and Marketplace no-replay. The path-filtered SQL workflow requires results for both exact test names. Use that disposable database workflow rather than connecting to tenant storage.
- Use published CI evidence for the release revision. Do not infer successful real vendor delivery from mocks, local synthetic responses, or a reserved row. Measure provider saturation and latency with existing telemetry after rollout before tuning capacity. Cross-process quotas, SDKs which ignore cancellation, and receiver-supported retries require independent contract evidence.
- Keep FND-065 active until these changes land, identified in-scope exceptions have explicit dispositions, and release/CI evidence is linked. Do not consider a comprehensive master dispatch part of this rollout.
