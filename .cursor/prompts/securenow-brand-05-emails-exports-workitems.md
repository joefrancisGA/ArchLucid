# SN-05 — Emails, exports, and work-item bodies (consumer artifacts)

**Do not** rename OpenAPI fields, webhook headers, or `com.archlucid.*` event types. **Do not** change `Email:FromAddress` domains (`@archlucid.net`). **Do not** rewrite GTM PDF samples under `docs/go-to-market` unless they are generated by the code you touch and the owner named them in this session.

Depends on **SN-01** for the UI-visible names. Backend needs a **product-line-aware or configurable** display name, not a repo-wide rename.

## Goal

Outbound artifacts a consumer reads (email subject/body product label, export footer “Prepared by …”, copied Jira/work-item titles) say **SecureNow** when the work originated in the Security product, and **ArchLucid** otherwise.

If the API cannot see UI product line, use this rule:

1. Prefer existing `Email:ProductDisplayName` / template `ProductName` — make the default depend on a **new optional** config `Email:SecurityProductDisplayName` = `SecureNow` **or** a request/header the UI already sends **only if one exists**.
2. Do **not** invent a new required API header in this prompt. If there is no product-line signal on the server, set **hosted Security deployments** (`NEXT_PUBLIC_ARCHLUCID_PRODUCT=security` is UI-only) via **appsettings / env on that deployment**: `Email:ProductDisplayName=SecureNow` for the Security website’s API **is wrong** (one API, two UIs).

**One API, two UIs (PL-05):** you cannot set a process-wide `ProductDisplayName=SecureNow` without breaking Architecture emails. Therefore:

- Add `ProductLineDisplayNames:Architecture=ArchLucid` and `ProductLineDisplayNames:Security=SecureNow` (or reuse UI constants in a **shared contracts** string only if already shared).
- Pass product line on **new** user actions from the UI when the payload already has a bag/metadata you can extend **without** an OpenAPI break. If the action is email from a Security-only route, stamp `security` there.
- For export footers generated from review-board / architecture packages: those stay **ArchLucid** (architecture product). Security-plane artifacts (infra evidence exports, operational packages) use SecureNow.
- If you cannot stamp product line without an OpenAPI change, **stop after documenting the gap** and implement only: (a) UI-copied work items, (b) export footer **templates** that already take `FirmDisplayName` / `ProductDisplayName`, (c) unit-level default strings for Security-named dispatchers. Do not sneak a breaking API field.

## Why

`EmailNotificationOptions.ProductDisplayName` already exists but defaults and many `DefaultProductName = "ArchLucid"` constants ignore product line. `WhitelabelConfiguration.DefaultFooterAttributionTemplate` is `Prepared by {FirmDisplayName} using ArchLucid`. Jira copy uses “ArchLucid Finding”.

## What to build

1. Single C# helper (new file) `ProductLineConsumerNames` or similar: Architecture → ArchLucid, Security → SecureNow. One class per file.
2. Email composers: use helper when product line is known; otherwise ArchLucid (safe default — Architecture is the historical product).
3. Security-plane export/generated-by lines: SecureNow. Architecture review-board packet: ArchLucid.
4. UI work-item copy: interpolate display name from SN-01 helper.
5. Tests: email dispatcher tests that currently hardcode ArchLucid — add Security cases; keep Architecture cases. No `ConfigureAwait(false)` in tests.

## Acceptance criteria

- Architecture review emails/export footers still say ArchLucid when product line is architecture or unknown.
- Security-plane user-visible generated-by / work-item titles say SecureNow when product line is security.
- `sales@archlucid.net` / `support@archlucid.net` unchanged.
- OpenAPI snapshot unchanged unless the owner explicitly allowed a new **optional** field in this session (default: unchanged).
