# SN-01 — Display-name helper + Security chrome (wordmark, titles, 403, outage)

**Do not** globally replace `ArchLucid`. **Do not** change Architecture chrome. **Do not** add a second logo SVG. **Do not** rename namespaces, env vars, or `NEXT_PUBLIC_ARCHLUCID_PRODUCT`. **Do not** collapse desktop review tabs. **Do not** imply CPA SOC 2 or a published third-party pen test.

If a prior **PL-02** session wired `PRODUCT_LINE_WORDMARK_ARIA_LABEL.security` to `ArchLucid Security — …`, **replace that consumer string with SecureNow** via the helper in this prompt. Do not ship both “ArchLucid Security” and “SecureNow” in Security chrome.

## Goal

Security UI (`NEXT_PUBLIC_ARCHLUCID_PRODUCT=security`, typically :3001) shows **SecureNow** as the product name in chrome that every signed-in consumer sees. Architecture UI (:3000) still shows **ArchLucid**.

1. One helper module owns display names (no scattered literals for the product word).
2. Masthead wordmark text + accessible name, document title template, 403, outage/timeout, and “Powered by …” / branding preview use that helper.
3. Tenant white-label still allowed: tenant name in the header; co-brand line becomes **Powered by SecureNow** in the Security process (Architecture stays **Powered by ArchLucid**).

## Why

There is no product-name token today. `ArchLucidLogo` hardcodes `WORDMARK_TEXT = "ArchLucid"`, `layout.tsx` uses `%s · ArchLucid`, and 403/outage copy names ArchLucid. Tenant branding (`OperatorHelpProductTextPolicy`) currently **requires** the token `ArchLucid` in help — do **not** “fix” help in this prompt (that is **SN-04**). Only chrome + recovery.

## What to build

1. New module `archlucid-ui/src/lib/product-line/product-line-display-name.ts` (one concern per file is fine if you split types):
   - `PRODUCT_LINE_DISPLAY_NAME`: architecture → `ArchLucid`, security → `SecureNow`
   - helpers: `productLineDisplayName(id)`, `productLinePoweredByLine(id)`, `productLineWordmarkAriaLabel(id)`, `productLineDocumentTitle(id)` (e.g. `SecureNow workspace` vs `ArchLucid workspace`), `productLineTitleTemplate(id)` (`%s · SecureNow`)
   - Point `PRODUCT_LINE_WORDMARK_ARIA_LABEL` at the helper or delete the stale “ArchLucid Security” string so there is one source of truth.
2. `ArchLucidLogo`: optional `wordmarkText` prop defaulting to architecture name; Security masthead passes SecureNow. Keep the existing mark geometry.
3. Operator top bar + auth wordmark + `AppShellClient` standalone/minimal chrome: aria-label from helper using `resolveProductLineId()` (client) or `resolveProductLineIdFromEnv()` (RSC/metadata).
4. Root `layout.tsx` metadata: `title.template`, default title, Open Graph `siteName`/`title` from **env** product line (build-time per process). Do not try to cookie-switch metadata.
5. Access-denied heading/body/mailto subject: interpolate display name. Architecture process unchanged.
6. Outage/timeout titles and `ArchLucid · UNAVAILABLE` footer: use display name.
7. Branding preview “Powered by” / “Generated by” / “Revert to … defaults”: product-line-aware **only if that settings page is visible in Security**. If the preview is shared, switch on `resolveProductLineId()`.
8. Vitest: helper unit tests; wordmark/aria; 403 copy; outage copy; layout metadata helper. Update snapshots that assert the old chrome strings **for security env**. Do not rewrite Architecture snapshots.

## Acceptance criteria

- Security process masthead visible word is **SecureNow** (unless tenant brand hides it, in which case “Powered by SecureNow” when that flag is on).
- Browser tab template is `%s · SecureNow` on the Security process and `%s · ArchLucid` on Architecture.
- `/403` and transient-failure chrome name SecureNow only when the Security product line is active.
- Architecture :3000 wordmark, titles, 403, outage still say ArchLucid.
- No C# identifier, webhook header, or `archlucid.net` email changes.
