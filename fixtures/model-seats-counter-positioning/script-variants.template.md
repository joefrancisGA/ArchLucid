## Script A — Accountability and governance

**Use when:** sponsor mentions audit, ARB sign-off, regulatory reconstruction, or "who approved this?"

**Opening:**

> You already pay for frontier models — architects should keep using them for exploration. ArchLucid is not a replacement for a chat seat. It is for when a design must survive review: committed manifest, evidence-linked findings, explainability traces, append-only audit, optional governance gates before handoff.

**Close:**

> Pilot question: can we produce a defensible review package faster, with a trail reconstructable six months later?

---

## Script B — Repeatable proof package

**Use when:** sponsor mentions repeat reviews, design iterations, or inconsistent review standards.

**Opening:**

> More model seats help individuals draft faster. ArchLucid helps the organization repeat architecture proof: structured pipeline to versioned manifest, sponsor export, two-review compare when the design changes.

**Close:**

> Pilot success is time to committed manifest and traceability — not beating ChatGPT prose in one session.

---

## Script C — Decision system vs chat (honest)

**Use when:** sponsor defaults to "just buy more Copilot" or challenges differentiation directly.

**Opening:**

> If your only need is exploratory Q&A, buy more seats — ArchLucid is the wrong tool. If your bottleneck is review preparation, traceability, and governance evidence, seats alone leave you reconstructing conclusions from chat history.

**Close:**

> Buy decision: chat assistant or proof engine your ARB can sign off on? We run honest bakeoffs on the same evidence — no claim we always win first-draft speed.
